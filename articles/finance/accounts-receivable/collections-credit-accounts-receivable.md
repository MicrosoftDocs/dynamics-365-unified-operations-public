# Collections in Accounts receivable

[!include [banner](../includes/banner.md)]

Accounts receivable collections information is managed in one central view using the Microsoft Dynamics 365 Finance Collections page. Credit and collections managers can use this central view to manage collections. Collections agents can begin the collections process from customer lists that are generated by using predefined collection criteria, or from the Customers page.

Before you begin to set up or work with collections, make sure you understand the following concepts:

- Customer aging snapshots contain aged balance information at a point in time.
- Collections customer pools help you organize your work.
- Collections agents can have their own customer pools.
- List pages organize collections customers, activities, and cases.
- All collections information for a customer is on one page and you can take action from that page.
- You can waive, reinstate, or reverse interest and fees in one step.
- You can create write-off transactions in one step.
- You can process not sufficient funds (NSF) payments in one step.

The following sections describe each concept.

## Customer aging snapshots

An aging snapshot contains the calculated aged balances for a customer at a point in time. You can view this information on the Aged balances list page and on the Collections page. You must create an aging snapshot before you can view information on the Collections list pages.

For each customer, an aging snapshot contains an aging snapshot header and detail records that correspond to each aging period in the aging period definition.

The aging snapshot header contains the total amount due, credit limit, packing slip amount, sales order amount, number of disputed transactions, and total amount of the disputed transactions for the customer account. The calculation of these amounts includes all transactions for the customer. The Credit information FactBox on the Collections page shows the total amount due, credit limit, packing slip amount, and sales order amount.

You create an aging snapshot detail record for each aging period in the aging period definition. Each aging snapshot detail record contains the aging period ID and the total amount of the transactions with dates that are in the aging period. You assign transactions to an aging period, such as 30 days past due. The date is relative to the Aging as of date that you specify when you create the aging snapshot. You can view this information on the Aged balances list page and in the Aged balances FactBox on the Collections page.

## Collections customer pools

Customer pools are queries that define a group of customer records that you can display and manage for collections or aging processes. Use customer pools to filter information on the Aged balances, Collections activities, and Collections cases list pages. You also use customer pools to filter the customer accounts that are included when aging snapshots are created.

## Collections agents

By default, users can view all customer information on collections list pages. Use collections agent records to determine the customer pools that are available to filter information on the collections list pages and on the Collections page.

A collections agent is a person who works with customers to make sure that payments are collected in a timely manner. Collections agents are workers who are assigned to users in the User setup page.

## Collections list pages

The following list pages help you organize collections information.

- Aged balances – The columns on the list page display customer balances and aged amounts by aging period. This information is stored in an aging snapshot. The aging periods are determined by the aging period definition that is used. The aging period definition comes from the customer pool, if you specify one for the pool query. If the pool doesn't have an aging period definition, the default aging period definition that you specify in the Accounts receivable parameters page is used. If you don't specify a default aging period definition, the first aging period definition in the Aging period definitions page is used.
- Collections activities – The columns on the list page display activities that are identified as collections activities. These activities are created by using the Collections page. Use activities to track the work that you do related to collections.
- Collections cases – The columns on the list page display information for cases that have a case category with a case type of Collections.

> [!NOTE]
> You must create an aging snapshot before you can view information on these list pages. The system displays information only for customers for whom you created an aging snapshot. You can filter the records that are shown on the list page as follows:
>
> - By default, a finance and operations user has access to all customers who have an aging snapshot.
> - If customer pools exist, you must set up a user as a collections agent to use the pools to filter information on the collections list pages. Information is limited to the customers who are included in the selected customer pool.
> - If you set up a user as a collections agent, only the pools that you select for that collections agent are available on the list page. If you select the Allow agent to view all customer pools toggle in the Collections agent page for the collections agent, all pools are available for that agent.

## Collections page

Use the Collections page to view, manage, and take action on collections information, activities, and cases for a customer.

The upper pane displays cases for the selected customer. The middle pane displays transactions for the customer. The lower pane displays activities for the customer. You can create collections cases to track collections information for one or more transactions and activities. You can filter the information in the upper and lower panes by case.

FactBoxes display aged balances and credit limit information for the selected customer. The aging snapshot stores this information. If necessary, you can update the aging snapshot with current information.

The Action Pane contains buttons that display related information for the selected customer, case, transaction, or activity. You can also perform common actions such as changing the collections status of a transaction, sending email correspondence through the integration with your email provider, reimbursing customers, processing NSF payments, and writing off uncollectible balances.

## Waive, reinstate, or reverse interest and fees

You can waive, reinstate, or reverse complete interest notes, or fees and transaction interest that are part of interest notes. You can make these changes from the Collect tab on the Action Pane on the All customers list page by selecting Interest note, Transaction interest, or Fee.

These adjustments affect only interest notes, and the interest and fees that they include. Use the steps in the “Create write-off transactions in one step” section to write off all of the charges that a customer owes.

For more information, see [Create an interest code with a range](tasks/create-interest-code-range.md) and [Process interest](tasks/process-interest.md).

## Create write-off transactions

You can write off bad debts by selecting **Write off** in the **Collections** form, and on the **Aged balances**, **Customers**, and **Open customer invoices** list pages.

When you write off transactions for a customer, the system automatically marks all transactions for the customer for settlement. The amount that you write off depends on the net amount of the marked transactions. You create the write-off transaction in a general journal, and it can contain up to three types of journal lines.

- The first type of journal line contains the customer write-off entry. If the marked transactions contain multiple combinations of currency code, dimension, and posting profile, you create a separate journal line for each combination.
- The second type of journal line contains the general ledger write-off entry. If the marked transactions contain multiple combinations of currency code, dimension, and posting profile, you create a separate journal line for each combination.
- The third type of journal line contains the general ledger write-off information for sales taxes. You create this journal line only if you select the **Separate sales tax** toggle in the **Accounts receivable parameters** page. If the marked transactions contain multiple combinations of sales tax payable account, dimension, and sales tax code, you create a separate journal line for each combination.

You create the write-off transaction in the transaction currency.

For more information, see [Create a write-off journal for a customer](tasks/create-write-off-journal-customer.md).

## Process not sufficient funds (NSF) payments

You can process NSF payments by selecting **NSF payment** in the **Collections** page. When you select this button, the payment is canceled. If an NSF fee applies for the customer, you create a charge transaction in a payment journal. The fee amount is based on the settings for the automatic charges. The automatic charges that apply for NSF payments are specified by the charges group that you select in the **Bank accounts** page for the affected bank account.
